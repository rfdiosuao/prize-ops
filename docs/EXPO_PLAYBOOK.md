# 游园会执行流程：先能跑，再让人看懂

适用：评委或观众走到展位前，反复观看或亲手操作作品的黑客松。它是现有「作品设计 → 执行冲刺 → 路演」之间的**现场展示环节**，不是所有赛事都必须走的第八阶段。配套 [案例与深圳站复盘](../05-stage/EXPO_CASES.md)、[完整复盘](../reviews/2026-09-24-EvoTavern深圳站-唤名SUMMON.md)。

这份流程由 2026 年 EvoTavern 深圳站 SUMMON 的赛后材料提炼。**“项目完成度 60%、讲解状态 40%”是参赛者给下一次游园会设置的备战配比，不是主办方公布的评分权重，也不是已验证的获奖公式。**实际评分、观众投票及晋级方式以本场官方规则为准。

## 入口：先确认赛制和承诺

开工前用一页纸写清：谁会来到展位、是否要观众亲手体验、每轮讲解限时、网络和电源、允许使用的硬件、评审依据与展示时段。没拿到官方答案的项目标“待核实”，不要用别场经验填空。若同时有集中路演，另外准备路演稿；展位不依赖长 PPT。

组队时，每人写出四天里**实际可投入的时段、独立交付物、最晚交付时间和替补责任人**。每天收工前按可运行产物验收。若承诺未交付，队长当天缩范围或转交，不让“有人在做”代替已交付。深圳站参赛者反馈有成员在四天赛期约两天有效投入；缺逐人工时记录，不能据此推断个人动机或单独解释比赛结果。可复用的教训是：选人时验证可投入时间，赛中及时验收与补位。

## 准备比例：60 / 40 的用法

| 备战面 | 本次建议投入 | 现场可检查的产物 |
|---|---:|---|
| **项目完成度** | 约 60% | 陌生人从入口发出请求，设备或页面给出真实反馈，结果可复核；连续重启、断网、换设备的降级边界写明 |
| **讲解状态** | 约 40% | 一句话说明谁遇到什么问题；30 秒内给出一个真实动作；能让对方复述价值；展示者精力充足，故障时能切换已标注的备用路径 |

这不是把四天工时机械切成六四。**主演示链路还没通时，先把它做到可重复，再分配讲解时间。**讲解也要提前做，不能留到项目完工之后。华丽网站、长视频或多路硬件都不能替代一条可重放的链路。

## 验收主链：一句话、一个动作、一个回执

团队只保留一个现场主路径，写成「观众做什么 → Agent / 系统做什么 → 哪台设备给出什么可见结果」。每一步标出运行环境、真实/模拟、负责人和失败时的出口。准备一张“主张—证据”卡：口播中每个“已实现”都能指向当场动作、日志或回执；设计稿、编译成功和本地单元测试分别标注，不冒充真机或公网通过。

对于跨设备项目，最短讲法是“从 A 输入 → 同一 Agent 判断 → 在 B 执行 → 回执显示”。如果现场只能运行本地 LIVE 演示，就明确说本地；公网仍是 SIMULATED 时，在展示页标清。录屏可作设备故障时的**录屏兜底**，不能说成实时执行。

## 展位交互：按观众愿意停留的深度展开

| 层级 | 展位要做到什么 | 验收办法 |
|---|---|---|
| 看见 | 一句话写明对象与作用，旁边有明确的开始动作 | 找未参与者看首屏，问他认为这是什么、下一步按哪里 |
| 试一下 | 展示者只说一句邀请，让对方完成一次输入 | 观察是否能自己找到入口，是否得到可理解的反馈 |
| 看结果 | 并排展示请求、Agent 决定、设备执行与回执 | 对方能分清“发出命令”和“实际完成” |
| 深入问 | 打开架构、代码、局限和下一步 | 每个技术主张都能落到实现或记录 |

层级是准备材料的方式，**不是对评委停留秒数的预测**。不必强迫每个路人听完全部讲解。找真实试用者，记下他在哪一步停住，再改入口、反馈或话术。

## 四天赛期的检查点

| 时点 | 完成判据 | 未达标时 |
|---|---|---|
| Day 0：组队/选题 | 赛制问题清单、四天可用时间表、每人负责的可交付物、主链与备选链 | 减少依赖临时硬件或单个队友的路径 |
| Day 1：最早真机冒烟 | 主链至少完成一次真实输入到真实反馈；硬件型号、SDK、供电、联网、停止方式实测 | 砍附加硬件、星图特效或新协议支线，先保一条演示路径 |
| Day 2：集成验收 | 从干净启动到完成回执连续演示，故障与重试有记录；未交付的成员任务当日重新分配 | 不继续扩功能，只修阻断路径的问题 |
| Day 3 / 游园会前一天 | **功能冻结**；不同设备和网络条件下走完整 Demo 至少 3 遍；一句话与简短讲解各排练至少 2 遍；备用电源、线、物料、录屏打包 | 演示降级到已验证版本，未验功能从口播移除 |
| 游园会当天 | 先自检入口、账号、设备状态和回执，再邀请观众上手；记下真实问题与故障 | 切已标注备用路径，现场不临时刷固件或加功能 |

### 前一晚的硬门槛：不熬夜

**游园会前一天不熬夜。** 在正常就寝前完成冻结、设备检查、三次完整演示、两次讲解彩排和装箱；预留充足睡眠时间，目标 7–8 小时。遇到阻断项，先缩演示范围或启用已验证备用版本，不用通宵换取一个未经回归的新功能。展示者的表达、判断和故障处理本身就是交付的一部分。

## 现场与赛后记录

现场只记录可以复核的观察：实际完成了几次完整演示、观众停在哪一步、问了什么、哪些设备或网络失败、评委给出的原话。不要从表情或停留时间推断打分。赛后按 [PrizeOps 复盘流程](../07-crystal/README.md)记录目标与结果、全流程时间线、做对的事、问题与改进、下次三项重点、证据与缺口，并单独检查**成员投入与交付、功能冻结时间、前夜睡眠和现场讲解状态**。没有官方评分明细就不验证“60/40 是得分权重”，只检验这套备战安排是否帮团队把作品展示清楚。

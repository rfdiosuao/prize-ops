# 前沿能力扫描（FRONTIER SCAN）

> 模块定位：跨阶段前置动作。在**定 idea 之前**先扫一遍当前技术水位，回答一个问题——**有哪些以前做不到的事，现在能做了？**
> 采集日期：2026-09-15（快照部分见附录，快照会过期，方法不会）
>
> ⚠️ **本模块不承诺任何模型的能力上限，也不构成选型建议。** 所有指标均来自公开材料，引用纪律见第六节。

---

## 一、为什么要有这一步

**每一届黑客松的获奖作品，都是那一届模型能力的函数。**

- 当模型只能写文本时，作品都是文本工具；
- 当模型能画图时，作品开始有视觉；
- 当模型能操作软件时，作品开始"替人做事"；
- 当模型能生成可交互的世界时，作品开始"造地方"。

**所以当能力阶梯发生跳变时，上一届的经验会变成误导。** 沿用旧假设的队伍会做出"上一届的加强版"，而真正的新形态不在他们的搜索空间里。

**这一步的产出不是 idea，是"可能性边界"。**

---

## 二、扫描三类对象

| 层 | 扫什么 | 跳变的信号 |
|---|---|---|
| **模型能力** | 推理、长上下文、长时程任务、工具调用 | 单任务耗时骤降 / 上下文量级变化 / 从"回答"转向"完成工作" |
| **生成能力** | 图像、视频、3D、可交互环境 | 从"生成静态产物"转向"生成可导航、有一致性的环境" |
| **编排与工具层** | Agent 框架、记忆方案、通信协议、执行沙箱 | **通常被忽略，但收益最高**（见第四节） |

> **最常被漏掉的是第三层。** 大多数人只扫第一层（模型），然后撞进红海。

---

## 三、扫描方法：能力 → 门槛 → 形态

不要罗列能力清单。要找出**每个能力跨过哪条线时，会解锁什么新形态**。

### 3.1 门槛识别表（填写模板）

| 能力 | 关键指标 | 上一代 | 当前 | **跨过了哪条线** | **解锁的形态** |
|---|---|---|---|---|---|
| 长时程任务 | 单任务可稳定执行时长 | — | — | 超过"N 分钟"后，"一键出结果"不再是唯一形态 | 可演示"过程"，可演示"持续性" |
| 长上下文 | 有效上下文量级 | — | — | 超过"能装下一整段长任务"后 | 跨阶段记忆成为可能 |
| 计算机操作 | 真实软件环境成功率 | — | — | 超过"能跑完完整工作流"后 | Agent 可以"替人操作"，作品可离开聊天框 |
| 环境生成 | 实时性 / 一致性时长 | — | — | 一致性从"秒级"到"分钟级"后 | 可探索空间成为可能 |
| 编排层 | 同一模型在不同 harness 下的分差 | — | — | **分差越大，说明瓶颈越在编排层** | 见第四节 |

**填这张表的纪律**：所有数字必须带**来源**与**采集日期**；跨不过门槛的项，老实写"未跨过"。

### 3.2 找"跨线"而不是找"最强"

**你不需要最强的模型，你需要找到最近刚跨过某条线的那项能力。**

因为刚跨线的地方，**大多数人的经验还是过时的**——这里存在时间差。而最强的那项能力，所有人都在用。

---

## 四、瓶颈转移判据（本模块最重要的方法）

### 4.1 判据本身

**如果同一个模型在同一个基准上，更换外部框架后得分出现巨大分差，那么当前瓶颈不在模型，而在编排层。**

**实证样本**（采集于 2026-09-15，见附录）：
同一前沿模型在 ARC-AGI-3 上，用提供方中立的标准测试框架得分 **62.7%**，加上厂商自家的上下文管理系统包裹后得分 **99.9%**。

### 4.2 这个判据为什么值钱

| 结论 | 行动含义 |
|---|---|
| 瓶颈在编排层 | **差异化机会在"你怎么组织记忆、上下文、工具"，不在"你用哪个模型"** |
| 编排层可以自己写 | 不需要训练模型、不需要特殊额度，**小队伍可以做出大区别** |
| 模型厂商自己也在打补丁 | 找它**发布材料里承认的尚未解决的问题**（往往是"实验功能"那一栏） |

### 4.3 具体操作

1. 读前沿模型的发布材料，**只找两类句子**：
   - "支持 X 中途变更仍保持 Y" → 说明 X 的稳定性是新能力
   - "实验功能 / 用于缓解 Z 痛点" → **说明 Z 还没解决**
2. 后者就是差异化机会。**前沿自己承认的缺陷，是最好的作品选题。**

## 五、可用性核查：能做 ≠ 你能用

**这是最容易翻车的一节。** 扫描出能力之后，必须逐项核实"你（在现场、在 96 小时内）能不能真的用上"。

### 5.1 核查表

| 核查项 | 要问的问题 | 不通过的后果 |
|---|---|---|
| **地区** | 是否限地区？ | 现场直接不可用 |
| **订阅/资质** | 是否需付费订阅、企业资质、或申请放行？ | 排队等到比赛结束 |
| **API 可得性** | 有没有公开 API？还是只有网页产品？ | **无法集成进作品** |
| **额度与成本** | 单次调用成本、配额上限 | 演示到一半耗尽 |
| **延迟** | 是否满足现场实时演示？ | 观众等待 → 走开 |
| **稳定性** | 是正式能力还是"实验功能"？ | 演示当天炸 |

### 5.2 硬规则

> **凡是没有公开 API 的能力，只能进"叙事与愿景"，不能进 Demo 主干。**

**Demo 主干必须建立在：有公开 API + 你已验证可用 + 有降级路径 的能力上。**

### 5.3 降级设计

对每一项依赖，都要写清"如果它挂了，屏幕上还剩什么"。
**一个在能力挂掉时仍然能演完的作品，才是可交付的作品。**

## 六、两条路线：选 B

| | 路线 A：用新能力做更多 | **路线 B：研究新能力还没解决的那个问题** |
|---|---|---|
| 做法 | 更强模型 → 更炫输出 | 前沿已承认的缺陷 → 做它的活体样本 |
| 同场竞争 | **绝大多数队伍在这里**（人人能调同一个 API） | 极少 |
| 对技术评委的价值 | 低（他们比你更熟这个 API） | **高（你展示了他们路线图上的边界）** |
| 差异化 | 低 | 高 |
| 风险 | 撞车 + 无纵深 | 需要说清"这不是吐槽，是实验" |

**判据**：**当整个赛场都在用同一个新能力优化同一个指标时，去看那个能力自己还没解决什么。**

> 注：这不是要你去批评前沿。**是要你去当它的边界样本。** 姿态上必须是"我们呈现现象"，不是"我们证明它不行"。

---

## 七、引用纪律

前沿数据最容易被引用翻车。**一条元规则**：

> **凡是对方可能比你更熟的数字，主动带上限定。**

| 常见错误 | 正确做法 |
|---|---|
| 用厂商自评数据当独立结论 | 标注"来自厂商发布材料" |
| 引用"特定测试框架下的高分"却省略框架限定 | **必须同时给出中立框架下的分数** |
| 把"实验功能"当稳定能力 | 明确标注"实验功能" |
| 把规格类数据与评测类数据混用 | 规格（上下文长度、价格）可直说；评测必须带来源 |
| 用"某能力已达 X%"推论"因此可以解决你的问题" | 加一句"实际效果由模型本体与运行调度框架共同决定" |

**主动说出限定不会削弱你，只会让你显得是这个圈子里的人。**

## 八、输出物：一页"能力—形态"对照表

扫描结束后，产出一页纸，格式如下：

```
【能力—形态对照表】  采集日期：____

门槛已跨过（可用）
  能力：______  指标：______  来源：______
  → 解锁形态：______
  → 我们的用法：______
  → 可用性核查：地区__ / API__ / 成本__ / 降级__

门槛未跨过（暂不可用）
  能力：______  原因：______

前沿自认未解决（差异化机会）
  缺口：______  证据（原文位置）：______
  → 我们的切入点：______

主线依赖（必须可用）
  依赖：______  降级路径：______
```

## 附录 · 快照（2026-09-15）

### A1 · 模型能力（示例：某前沿模型，2026-09-03 发布）

| 指标 | 值 |
|---|---|
| 上下文 | 1,050,000 token |
| 最大输出 | 128,000 token |
| 电脑操作（OSWorld 2.0） | 72.6%，单任务约 40 分钟（上一代 65.7%，约 75 分钟） |
| 其他 | ScreenSpot-Pro 92.7% / Agents' Last Exam 59.3% / Terminal-Bench 4.0 57.9% |
| 工具 | web search、file search、image generation、hosted shell、computer use、skills、MCP |

**注意点**：厂商同时强调"**支持任务中途叠加新增需求，最大程度保留原有任务约束**"——这句话说明"长任务中的目标保持"是这一代的新能力。

### A2 · 生成能力：世界模型线

| 系统 | 能力 | 一致性/时长 | 可用性限制 |
|---|---|---|---|
| Genie 3 | 实时可交互 3D 环境，自由导航，涌现物理，会话内记忆 | 一致性 8 个月内从秒级到分钟级 | **限地区、需高价位订阅、无公开 API** |
| Genie + 地图影像锚定 | 以真实街景为锚生成可探索世界 | 单次约 60 秒 | 同上，且地点受限 |
| Marble | 文字/图/视频/草图 → 可探索 3D 世界，可导出 mesh 或 Gaussian splat | 静态持久 | 面向企业付费客户 |
| （同类）Atlas | 文本+图像+视频+3D 预训练；显式相机控制；场景重建 | 分钟级视频 | early access，需申请 |

**行业判据（值得复用）**：世界模型按输出分三类——
**Renderer**（输出像素，被评判的是视觉保真度）｜ **Simulator**（输出状态：几何/物理，被评判的是**结构准确性**）｜ **Planner**（输出动作，被评判的是任务成功率）。
行业内的明确说法：**Renderer 不能被信任用来设计建筑或训练机器人。**
→ **当你声称"生成的世界可用"时，必须说清你造的是哪一类。**

### A3 · 瓶颈转移的证据

同一模型，ARC-AGI-3 基准：

| 测试条件 | 得分 |
|---|---|
| 提供方中立的标准测试框架 | 62.7% |
| 加上厂商自家的上下文管理系统 | 99.9% |

**同一模型、同一基准，差 35 个百分点。** → 瓶颈在编排层（见第四节）。

### A4 · 前沿自认的未解决缺口

同一份发布材料中出现了一行：**"长任务上下文记忆（实验功能）——用于缓解超长任务信息压缩失真痛点"**。

**读法**：前沿承认**长任务下的信息压缩失真尚未解决**，正在用外部上下文管理打补丁。
→ 按第四节 4.3 的操作，**这一行就是差异化机会的位置**。

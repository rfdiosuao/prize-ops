# 游园会案例：SUMMON 深圳站

配套流程：[游园会执行流程](../docs/EXPO_PLAYBOOK.md)。本案例用于校准排期和现场演示，不用于推断评委给分。记录基于参赛者陈述、四份赛后材料和 [SUMMON 公开仓库](https://github.com/rfdiosuao/summon-protocol)；材料写于不同日期，早期状态不能覆盖后续进展。

## 情境与目标

EvoTavern 深圳站赛期为 2026-09-21 至 09-24，团队为 SUMMON 准备“Agent 从输入设备接收指令，再让另一具设备执行并回报结果”的体验。入口、云端、客户端、固件、官网与机械臂都在四天里推进。要给游园会观众看的主张可以压缩成：**对 Passport 说一句话，Agent 在已授权的机械臂上完成一个短动作，并显示真实回执。**

## 观察到的过程

| 截面 | 材料能够证明什么 | 不能据此声称什么 |
|---|---|---|
| 9/22–9/23 Passport 调试记录 | 真机备份、刷写、外设初始化；接入 Skill 的 18 条文档/实现差异经修复复验闭环；语音与配网在持续调试 | 这时整个云端到机械臂链路已稳定通过现场验收 |
| 9/23 接入方记录 | 接入适配器 30 项离线验证和线上问题复验；官网目录中可见在线 Agent；资料仍列硬件主链未完成 | 离线自检等于真实硬件闭环 |
| 9/24 仓库后续提交 | README 记录 Passport 语音控制 B601-DM；本地 LIVE 演示文档记录显示屏→机械臂交接；[9/24 机械臂演示迭代提交](https://github.com/rfdiosuao/summon-protocol/commit/0575582)涉及实机姿态与运动窗口 | 公网官网与本地 LIVE 是同一环境，或该提交单独证明 Passport 全链和游园会每轮都稳定复现 |
| 9/26 本地复跑材料 | 契约校验、参考端自检通过；16 个单测模块中 14 个通过、2 个异常；公网冒烟因缺本地配置未执行 | 全套测试绿灯或现场评分已知 |

**时间线冲突的处理：** 较早的复盘包把机械臂列为“只能手动”，而公开仓库 9/24 后的版本记录了实机动作。它们描述的是不同时间、不同演示环境。是否在游园会当天由陌生人完整走通、走通多少次，材料没有统一记录，仍待补现场日志或视频。

## 可复用的做法

1. **用外部接入者视角跑 Skill。** 18 条问题集中在文档与实现不一致，说明“开发者自己知道怎么用”不能替代接入者照文档走通。下次将示例命令纳入自动验收。
2. **保留真机与控制器回执。** 对硬件展示，“命令发出”不是完成；真实姿态、动作边界和 `controller_feedback` 才能支持完成主张。展示页应并排显示输入、决定和回执。
3. **把实现状态按环境标清。** 本地 LIVE 链路、云端 SIMULATED 目录、录屏兜底各有用途，标签清楚才能让观众信任当前演示。

## 失误与纠偏

| 失误或缺口 | 对游园会的影响 | 下次具体改法 |
|---|---|---|
| 四天里并行推进官网、协议、固件、语音、配网、客户端和机械臂 | 每条链都要集成，稳定演示和彩排时间被挤压 | Day 1 锁一条主链；其他设备是可删支线；Day 2 连续演示不过就停止加功能 |
| 成员实际投入与预期不匹配：参赛者称有成员四天中约两天有效投入；赛前承诺与逐日交付未记录 | 可用产能低于计划会挤压集成和讲解准备，具体影响程度不能量化 | Day 0 写时间表与交付物，Day 1 每人拿出可运行产物；未达标当天补位或缩范围。缺逐人工时记录，不能据此归咎个人动机或单因解释结果 |
| 文档、口播与真实版本有漂移；部分早期复盘停在 9/23，后续实机成果未及时回填 | 展位上容易把计划说成完成，或者把已完成说成未完成 | 一页“主张—版本—环境—证据—限制”表作为唯一口径；每次发布/演示更新它 |
| 测试与现场证据分层不清；9/26 本地复跑仍有 2 个异常模块 | “代码有了”容易被当“全链稳定”，故障时无明确降级 | 保留干净启动的三次完整演示记录，注明输入设备、目标设备、网络和回执；把未测项从承诺里删掉 |
| 最后阶段持续修改硬件/固件与展示内容 | 睡眠和讲解状态可能受损；材料没有可核对的睡眠时长，不作已发生的断言 | **游园会前一晚不熬夜**；提前冻结，完成三次主链演示与两次讲解，剩余问题用已验证版本兜底 |

## 案例 1 · 游园化赛制的真实样本

**来源**：公开报道（媒体稿），采集于 2026-09-15。**证据等级：third_party。** 未取得主办方赛制文件，细节以该赛事官方为准。

### 事实（报道所述）

- 某地黑客松联赛（2026 年 5 月），近 50 支高校团队、约 200 名开发者，24 小时制。
- **赛制关键改动**：「取消传统 PPT 路演，采用游园会公开展示模式，把评判权交给观众与体验者。」
- 现场创意覆盖生活服务、健身健康、就业指导、出行旅游等方向。
- 其中一支队伍（高中生团队，24 小时完成）做了「人体动态捕捉 + 动作纠正 + 个性化计划 + 打卡激励」，属健身健康方向。

### 可提取的逻辑

1. **"取消路演 → 改为游园 + 观众评判"是一种真实存在的赛制变体。** 这意味着：**把全部准备投在 deck 与口播上，可能是押错**。
2. **观众评判制会放大"当场可玩"的权重**，并且会显著利于**零门槛、能围观、有即时反馈**的作品形态。
3. **此类赛制对"作品形态"的筛选力，强于对"技术深度"的筛选力。** 因此在这类赛制里，"选什么形态"比"技术多深"更早决定结果。
4. **同一形态可能同时被多支队伍采用**（本例中健身/动作类即为一例）。形态选择时必须先做**同质化查重**，见案例 3。

### 迁移动作

- 拿到赛程后第一件事：确认**是否存在路演环节、观众票绑定哪个奖、晋级由谁决定**。
- 若为纯游园 + 观众评判制，把"呈现层"提升为**一等公民**，而不是收尾工作。

## 案例 2 · 把长时程现象压缩成 60 秒

**背景**：某参赛作品的核心现象是「一个记忆容量被硬性限制的 Agent，在 96 小时里因为反复压缩而逐渐记错」。**现象只有放在时间轴上才成立。**
**证据等级：first_party（参赛方自述，尚未参赛，无结果数据）。**

### 困境

| 困境 | 具体表现 |
|---|---|
| 现象不可即时演示 | 陌生人站在展位前 60 秒，看不出"它在慢慢记错" |
| 概念抽象 | "记忆失真"是机制描述，不是可见事件 |
| 同类竞品形态可读性更强 | 同场的可玩型作品天然更抓人 |
| 讲述者表达不稳定 | 需要向每人重复讲解，第 40 遍开始走样 |

### 解法（抽象后）

**核心动作：把"需要时间才能显现的现象"，改造成"一次操作就能显现的对照"。**

1. **制造对照，而不是展示过程。**
   不做"看它 96 小时的变化"，做"你刚说的 / 它记得的" 并排两栏。**过程不可展示，但过程的结果可以并排。**
2. **让观众亲手制造那个现象。**
   不让观众"看它记错"，让观众**说一句话 → 让它回忆 → 自己看到变化**。观众从旁观者变成肇事者，理解成本归零。
3. **把结果实体化，做成需要"翻过来"的物件。**
   一件拿在手上、翻过来才知道结果的实物，替代一段屏幕上的文字说明。**陌生人不需要被邀请就会去翻它。**
4. **把"时间"交给视频。**
   现场无法演示时间维度 → 视频的唯一任务就是**压缩时间**（延时、曲线、状态迁移），而不是解释项目。
5. **把讲解从"说"改成"递"。**
   见 `docs/EXPO_PLAYBOOK.md` 第四节四层台阶。讲述者只背 2 句 + 1 个动作。

### 可迁移的判断

| 判断 | 适用条件 |
|---|---|
| 现象依赖时间 → 用对照替代过程 | 任何"渐变/累积/演化"型作品 |
| 抽象机制 → 找一个人人有的日常经验作锚 | 所有需要科普的机制 |
| 讲解负担重 → 把解释搬进屏幕与实物 | 所有需要向陌生人反复解释的作品 |

## 案例 3 · 红海创意的反转改造

**背景**：一个外部方案「AI 教练 / 姿态识别 + 动作纠正」。
**证据等级：first_party（评估过程自述）。同质化判定基于公开检索，采集于 2026-09-15。**

### 第一步：同质化查重

检索该形态在公开黑客松里的结果，发现它**已被多次验证能拿冠军**：

| 公开案例 | 结果 |
|---|---|
| 某大学创投黑客松「AI Gym Coach」（姿态关键点 + 规则引擎 + 大模型反馈） | 全场大奖 |
| 某欧洲黑客松「AI 瑜伽教练」（实时姿势反馈 + 语音指导） | 第 1 名 |
| 某地黑客松「人体动态捕捉 + 动作纠正 + 个性化计划」 | 由高中生团队 24 小时完成 |
| 开发者平台的同类完赛作品（姿态关键点 + 语音反馈） | 多例 |

**关键推论（本案例最有价值的一句）**：

> **一个形态"已经被验证能赢"，恰恰说明它会变成同场最可预测的一张牌。技术门槛越低，撞车概率越高。**

### 第二步：定位真正的缺陷

| 缺陷 | 性质 |
|---|---|
| 赛道归属不清 | 若投"具身/硬件"赛道，纯软件形态有失格风险 |
| 主题穿透力弱 | 是工具，不是对命题的回答 |
| **核心主张不可验证** | "它知道哪里不对"——缺少 ground truth，赛内无法验证。**科学性评审会直接问死这一条** |
| 无技术勇气 | 调用的都是成熟现成模型 |
| 无记忆点 | 该视觉形态已无新鲜感 |

### 第三步：反转改造（抽象为可迁移的方法）

**方法：不去做一个"更好的 X"，去追问"X 的标准从哪来"。**

| 原形态 | 反转后 |
|---|---|
| 教练按**预设**的正确姿势纠正你 | 教练的"正确"**不预设**，而是**从现场人群的观测中统计生成** |
| 观众是受评者 | **观众可以投票修改标准**，标准随大众漂移且可见 |
| 结论：你做错了 | 结论：**你偏离了"大多数人的平均"——而那是被投票出来的** |

**这一改同时解决了四个问题**：

| 问题 | 如何被解决 |
|---|---|
| 主题穿透力 | 从"一个工具"变成"关于标准如何被定义的追问" |
| 可验证性 | 标准的来源、样本量、判定比例**全部可审计** → 经得起读代码 |
| 同质化 | 从"又一个拍照教练"变成"关于拍照教练的伦理装置" |
| 自身重复风险 | 与原方案的机制完全不同（一个是提醒，一个是质疑标准） |

### 可迁移的反转模板

| 红海形态 | 反转方向 |
|---|---|
| 做更好的检测器 | 追问"标准"从哪来、谁有权定义 |
| 做更准的推荐 | 追问"偏好"是被发现的还是被塑造的 |
| 做更强的助手 | 追问"协助"与"替代"的界线在哪 |
| 做更全的记忆 | 追问"遗忘"的代价与必要性 |

**通则**：**当整个赛场都在优化同一个指标时，去质疑那个指标本身。**

## 案例 4 · 困境—解法对照表

| 你遇到的困境 | 去哪一节 | 一句话解法 |
|---|---|---|
| 不知道这场比赛要不要准备路演 | Playbook §1.1 | 开赛第一天问掉 5 个问题 |
| 路过的人不停留 | Playbook §4.3 / §5.3 | 改展位，不改你 |
| 我讲不清、别人听不懂 | Playbook §4 | 从"说"改成"递" |
| 核心价值要 60 秒以上才能体现 | 本库案例 2 | 用对照替代过程 |
| 我的方向好像很多人也在做 | 本库案例 3 | 反转标准，不做更好的同类 |
| 评委问"你怎么证明" | Playbook §3 / §8.1 | 把判定依据做成可审计的，并主动说明分寸 |
| 现场翻车 | Playbook §7.1 | 视频兜底 + 双机 + 本地降级 |
| 没时间做呈现了 | Playbook §9 | 呈现层不是装饰，冻结点必须提前 |

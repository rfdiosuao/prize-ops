# EvoTavern 深圳站 · 唤名 SUMMON 复盘：工程做出了进展，展示闭环应更早锁定

记录日期：2026-09-27。项目：[唤名 SUMMON](https://github.com/rfdiosuao/summon-protocol)。赛期：2026-09-21 至 09-24。本文汇总四份由不同协作者整理、覆盖时段不同的赛后材料，并核对项目公开仓库。材料是过程证据，不是赛事官方评分。

## 目标与结果

目标是让 Agent 接收 Passport 语音，经 SUMMON 通道控制已授权的另一设备，现场能直观看到输入、决策、机械臂动作与回执，并展示跨设备交接和经验沉淀。

截至公开仓库 9/24 的实现记录，Passport→Agent→B601-DM 的语音控制和本地 LIVE 显示屏→机械臂交接已进入可演示状态，机械臂动作有控制器完成回执。[项目 README](https://github.com/rfdiosuao/summon-protocol/blob/main/README.md)、[本地实机演示说明](https://github.com/rfdiosuao/summon-protocol/blob/main/docs/ARM-LIVE-DEMO.md)均记录此边界。公网官网当时仍是 SIMULATED 环境，不能把本地 LIVE 直接说成公网链路已验收。

**比赛名次、评委评分、游园会现场成功演示次数及观众反馈未见可核对记录。** README 把“Passport 控臂”记在 9/22，而一份 9/23 的接入方材料仍写主链未完成；9/24 提交记录有后续实机进展。这说明材料是不同版本截面，仍需现场录像或运行日志确认精确完成时间，不应拿早期阻塞否定后续成果，也不应把仓库中的能力自动当成当日每轮展位体验。

## 做对的事

1. **核心想法有可见物理结果。** Passport 语音到机械臂动作比“Agent 可以跨设备”的概念图更容易被理解；真实控制器回执让“动作完成”有验证点。下次继续先设计一条观众能亲手触发、能看到结果的主路径。
2. **按外部接入者视角验文档。** 一份测试材料记录 18 条接入说明与实现不一致，修复后复验闭环；这类问题往往只在陌生人照 Skill 操作时暴露。下次将文档示例命令和返回状态纳入自动检查。
3. **实机与模拟环境开始分清。** 仓库把本地 LIVE、公开 SIMULATED、录屏/备选路径分开记录，并要求控制器回执；这能减少现场过度承诺。继续保持“已实现、仅本地验证、仅设计”三种标记。
4. **发现硬件支线不适合演示时有收缩意识。** 眼镜等方向被评估后未成为必须依赖的主链；这类判断应提前到 Day 0–1，而不是临近展示才做。

以上是从过程证据提取的可复用做法。没有评委评分，不能说其中某一项导致具体赛事结果。

## 做错的事与改进

| 问题 | 影响 | 下次做法 |
|---|---|---|
| **主范围过宽。** 四天内并行做协议、官网、固件、配网、语音、跨设备客户端和机械臂 | 集成与回归被挤到最后，观众可反复上手的路径不容易提前稳定 | Day 0 只定一条 P0：语音输入→Agent 判断→一台设备动作→真实回执；其余写为可删项。Day 1 完成真机冒烟，Day 2 连续演示不过就停止加功能 |
| **成员实际投入与预期不匹配。** 参赛者反馈一位成员在四天赛期约两天有效投入；赛前承诺与逐日交付未记录 | 可用产能低于计划会挤压集成和彩排；本次具体影响程度不能量化 | Day 0 明确每人可投入时段、独立交付物与替补；每天看可运行产物，未达标当晚重分配或缩范围。不点名推断动机，也不把赛果单因归责于队友 |
| **版本和证据散在多份文件。** 9/23 复盘停留在“主链未通”，后续仓库已有实机演示；口播和对外材料有与实现错位的风险 | 现场可能说大、说旧，或把已完成成果讲不出来 | 保留一页唯一权威的“主张—版本—环境—证据—限制”，每次演示前由负责人核对；公开文档随演示版本更新 |
| **测试层次容易混淆。** 编译、离线自检、线上服务探测、真机动作、游园会观众操作是五层不同证据 | 用“测试通过”概括全部能力，无法判断现场可用性 | 每层单独记录。D-1 从干净启动完整演示 3 次，记录设备、网络、输出与回执；不把早期测试数字跨版本相加 |
| **展示者状态缺硬门槛。** 材料有深夜持续调固件的记录，但无最终前夜睡眠时长 | 疲劳会直接影响口播、反应和故障切换；本次影响程度未量化 | **游园会前一天绝不熬夜。** 提前冻结版本，完成三次主链演示、两次讲解彩排与物料打包，正常就寝；未验功能从展示中删除 |

## 游园会的工作判断

下一次把准备重点按**项目完成度约 60% / 讲解状态约 40%**安排。这是参赛者从本次经历提炼的**备战配比**，不是 EvoTavern 官方评分权重。完成度指陌生人能触发真实路径并看到结果；讲解状态指一句话定位、短演示、邀请上手、现场排障和展示者精力。没有可运行主链时先保主链；主链稳定后再投入讲解、展位与录屏。不要为多一个功能牺牲前夜睡眠。

## 下一次只抓三件事

1. **Day 0 锁人和锁主链。** 每名成员写出四天可用时间、可交付物、交付时间与替补；一页纸画出唯一演示主路径。判据：Day 1 每人有可运行产物，真机主链至少跑通一次。
2. **Day 2 让陌生人走完主链。** 用干净启动重复演示，记录输入、Agent 决定、目标设备回执和失败路径。判据：未参与开发的人能独立完成一次；如果做不到，就减功能，不延长范围。
3. **D-1 冻结、彩排、睡觉。** 3 次完整演示、2 次掐时讲解，备好电源/网络/录屏和主张证据表；正常就寝，预留充足睡眠。判据：游园会早上无需刷固件或改代码即可开场。
